# Desenvolvimento e lançamento

## 1. Definir

- [ ] Problema, público e primeira versão definidos.
- [ ] Critérios de aceitação registrados.
- [ ] Tecnologia escolhida e dependências necessárias identificadas.

## 2. Construir

- [ ] Implementação completa do escopo da versão.
- [ ] Tratamento dos erros relevantes.
- [ ] Documentação atualizada com os comandos reais.
- [ ] Nenhum recurso futuro apresentado como disponível.

## 3. Verificar

- [ ] Comportamentos principais e falhas relevantes verificados.
- [ ] Verificações automatizadas adequadas à tecnologia.
- [ ] Demonstração revisada visualmente quando houver interface.
- [ ] Resultados e limites registrados.

## 4. Preparar publicação

- [ ] Segredos, dados pessoais e conteúdo de terceiros revisados, incluindo histórico.
- [ ] Exemplos e imagens usam dados públicos autorizados ou fictícios.
- [ ] Licença e condições de distribuição definidas.
- [ ] Instalação e uso reproduzidos a partir das instruções.
- [ ] Custos de hospedagem e serviços avaliados quando existirem.

## 5. Lançar

- [ ] Versão inicial identificada, por exemplo v0.1.0.
- [ ] Notas de lançamento com recursos, requisitos e limitações reais.
- [ ] Artefatos de distribuição conferidos quando existirem.
- [ ] Link público funcionando.
- [ ] Apresentação adicionada ao perfil após o lançamento.

## 6. Manter

- [ ] Problemas acompanhados por Issues.
- [ ] Dependências revisadas conforme risco e necessidade.
- [ ] Próxima versão definida por melhorias úteis e retorno dos usuários.

## Organização

Use main como versão estável e branches curtas para alterações. Em trabalho pelo Codex, use o prefixo codex/. Adicione um quadro de Projects quando houver tarefas suficientes para justificar o acompanhamento. Ative CI e proteção de branch depois de existir uma verificação real que possa ser exigida; não crie checks vazios.
